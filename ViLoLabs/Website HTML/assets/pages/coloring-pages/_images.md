SIZE — SET IT IN THE TOOL, NOT JUST THE PROMPT: image generators mostly
ignore pixel sizes written in the prompt and use their own aspect-ratio
setting. Pick the setting closest to A4 (height ÷ width ≈ 1.41):
  ✅ good:  2480x3508 · 1240x1754 · 864x1232 · 1055x1491  (A4 / ≈A4)
  🆗 ok:    2:3 (e.g. 832x1248) or 3:4 (e.g. 1024x1365) — a little white margin
  ❌ avoid: 9:16 (768x1376, 1080x1920) — prints narrow; 1:1 square
Check after download: height ÷ width should be 1.33–1.50.

REFERENCE THUMBNAIL — TWO ITERATIONS (2026-05-26):

  Iteration 1: Earlier prompts said "small fully colored reference
  thumbnail" in the corner. Too tiny to read distinct colours on.

  Iteration 2 (current): User reported that the larger-thumbnail
  prompt was leaking colour INTO the main outline area — kids
  received pages where some regions were already coloured in.

  Root cause: mentioning "fully colored reference of the same X"
  too close to the subject description confused the AI into
  partially colouring the main image.

  Fix applied to all 141 prompts:
   1. Added a CRITICAL clause: "MAIN coloring area is ENTIRELY BLANK
      black and white line art with absolutely NO colour fill anywhere,
      every region inside the main outline stays pure white untouched
      ready for the child to colour"
   2. Stated "The ONLY coloured element on the entire page is..."
      BEFORE describing the thumbnail
   3. Thumbnail kept at 25% page width with all regions clearly visible
   4. Removed the redundant trailing "of the same X in bright flat
      cartoon colors inside a thin rounded frame box" — replaced with
      a clean "the thumbnail itself rendered in bright flat cartoon
      colours"

  Apply this exact wording if you regenerate any old pages.

ITERATION 3 — QC BEFORE SHIPPING (2026-10-08):

  The CRITICAL clause REDUCES colour leak but does NOT stop it. Of 9 new
  pages, 2 still came back with fills in the main art (fox: orange inner
  ears; coral: yellow/blue coral). The AI also drifts on subject: coral
  came back as a clam, hermit crab sat in a clam shell. Every new image
  gets this check before it is ticked DONE:

   1. SHAPE — A4 portrait (ratio ~1.41: 2480x3508 or 864x1232). Taller
      images (e.g. 768x1376) still render (object-fit:contain, no crop)
      but print narrower with white side bars. Ask for A4 explicitly.
   2. LEAK — main area has 0% colour outside the top-right box. Zoom the
      ears/eyes/small details — leaks hide in small enclosed regions.
   3. SUBJECT — main art is clearly the named subject, not a near-copy of
      another page, and is factually right (it's an educational sheet).
   4. MATCH — corner thumbnail shows the same subject/pose as the main art.
   5. FRAMING — nothing important cut off at the page edge.
   6. NO CARRY-OVER — generate each page in a FRESH chat/session. In the
      same session the tool reuses the previous image (parrot came back
      with the raccoon's body + striped tail; clam/coral/hermit crab all
      shared one clam drawing).

  Small flat leaks (fox ears) can be whitened by script without touching
  lines or the thumbnail — original kept in
  Resources/library-originals-backup/coloring-pages/. Wrong subject or
  big leaks = regenerate, don't patch.
